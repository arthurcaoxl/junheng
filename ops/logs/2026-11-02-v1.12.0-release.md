## 发布背景

- 业务目标：未来平台开展研究与白皮书数据池，需要用户的明确授权；同时为不打扰用户，采用“总授权”机制——只向从未表态的用户征求一次，同意与拒绝都永久放行。
- 取代 v1.11.0 的页面级 localStorage 弹窗（无拒绝路径、双重拦截冲突）。

## 发布内容

- 入口门禁：`CheckInGateLink` 统一包裹 Hero 与入口区链接，点击 `preventDefault` 后查云端表态；`useConsent` Hook 管理“查询 → 弹窗 → 写库 → 放行”状态机。
- 云端判据：`services/consent.ts` 的 `fetchCloudConsent()` 读取 `checkin_sync.consent_granted`（true/false 放行，null 弹窗）；无会话或查询失败降级读本机留痕，老用户不被重复骚扰。
- 表态持久化：`saveCloudConsent(granted)` 采用“查行 → 行存在 update / 无行 insert”分流（规避未知表约束下裸 upsert 的静默失败风险）；同意/拒绝均写云端 + 本机双留痕，保证“绝不再弹”。
- 弹窗重写：`ConsentDialog` 按新 Spec 重写（标题“开启前，请确认数据授权”，勾选文案一字不差默认不勾选，新增“暂不参与”次按钮），复用现有 `.consent-*` 样式。
- 合规兜底（`refactor(sync)`）：`writeCloudSnapshot` 建档 insert 默认写入 `consent_granted: false`——URL 直达/未表态用户的打卡数据建档即标记未授权，绝不误入研究池；同步流程永不回写 consent 列（表态写权限由 saveCloudConsent 独占）。
- 清理：移除页面级旧弹窗挂载与废弃的 `grantResearchConsent`；删除被取代的 `consent-dialog.test.tsx`。
