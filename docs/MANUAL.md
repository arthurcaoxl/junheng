# 菌衡计划网站功能使用手册

> 适用基线：`cd41e7a`。本手册描述当前代码中已经存在的功能，用于用户、教练与管理员的操作培训和上线前核对。规划中的重构功能不属于当前操作能力，统一见 `docs/WORKLOG.md` 的“重构 Backlog 冻结”记录。

## 一、入口与角色

| 角色 | 当前入口 | 主要用途 |
| --- | --- | --- |
| 用户（User） | `/check-in` | 提交产品码激活申请、完成 21 天打卡、查看激活状态 |
| 用户（User） | `/user-center` | 查看健康统计与个人资产，管理账号安全、数据授权和跨设备同步 |
| 教练（Coach） | `/coach/codes` | 查看本人未激活产品码、可用数量与补货提示，复制码面 |
| 管理员（Admin） | `/admin/check-in` | 平台码池、激活人工审核、教练托管、脱敏雷达、统计与导出 |

### 权限边界

1. 用户只能处理本人的激活、打卡、备份和恢复，不应使用教练或管理员账号。
2. 教练码库使用本人邮箱验证码登录，只展示属于该教练的码库信息。
3. 管理端仅限获得权限的管理员使用。生成、划拨、审核、托管等操作必须核对对象和数量，不得代替用户伪造打卡数据。
4. 管理端雷达只使用服务端返回的脱敏指标，不得通过页面、接口或导出文件补充用户原始身高、体重和打卡记录。

## 二、用户端 SOP（User）

### 2.1 首次激活：提交产品码人工审核

1. 打开 `/check-in`，找到产品码激活区域。
2. 输入盒内产品码，核对后提交人工审核。
3. 页面提示审核中后，等待管理员处理。审核未完成时不要重复提交，也不要把产品码转发给他人。
4. 审核期间打卡入口受激活状态限制，应按页面提示等待结果。
5. 审核通过后，产品码绑定对应教练，页面显示已绑定状态和可用打卡额度，随后即可正常打卡。
6. 若申请被拒绝或页面显示异常，先核对产品码和当前账号，再联系教练或管理员核查，不要连续尝试他人的产品码。

当前激活说明为：输入盒内产品码并提交人工审核。审核通过后将绑定对应教练指导，每日记录腰围、体重等数据，形成动态的健康指标。

### 2.2 每日打卡

1. 进入 `/check-in`，确认当天日期和 21 天进度。
2. 首次使用时按页面要求填写姓名或网名、开营日、体验官代码等基础信息。
3. 按当天真实情况填写体重、腰围、三餐、饮水、运动和作息等内容。
4. 衣物扣减按当天快照处理。修改今日衣物不会改写已经保存的历史日期快照；补录或修改历史内容时，应逐项核对日期。
5. 保存后检查页面反馈，不要仅凭离开页面或刷新前的输入状态判断数据已经保存。
6. 次日继续在同一入口记录，形成连续的 21 天数据。

### 2.3 本机保存、云端备份与恢复

1. 打卡内容支持本机自动保存，但本机保存不等于跨设备备份。
2. 需要换设备或防止浏览器数据丢失时，先在用户中心绑定邮箱并完成云端备份。
3. 在新设备上使用原绑定邮箱完成验证，再按页面提示恢复云端数据。
4. 恢复后核对体验官代码、最近打卡日期和关键指标，确认无误再继续填写。
5. 清理浏览器数据、使用无痕模式或更换设备前，必须确认云端备份状态；没有完成备份时，不要清理原设备数据。
6. 邮箱用于登录和跨设备找回，应使用本人可长期访问的邮箱，不要与教练或其他用户共用。

### 2.4 用户中心

进入 `/user-center` 后可进行以下操作：

- 查看健康统计、BMI 与个人资产等汇总信息。
- 管理账号安全、数据授权和跨设备同步。
- 核对激活和教练绑定状态；已激活用户不应重复申请其他产品码。
- 指标尚未形成或数据不足时，以页面的空状态或待完善提示为准，不将空值当作 `0`。

### 2.5 用户常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提交产品码后无法打卡 | 先查看是否仍在人工审核中；未通过审核前不要重复提交 |
| 更换设备后看不到原数据 | 使用原绑定邮箱恢复；未绑定邮箱时联系管理员核查，不要新建多套身份 |
| 修改今日衣物后历史数据变化 | 正常流程下今日修改不应改写历史快照；保留日期和页面状态，交由管理员复核 |
| 页面显示审核失败或申请受限 | 停止连续重试，记录页面提示，由教练或管理员检查申请状态 |
| 数据显示为空或 `--` | 先补齐本人数据；空值不代表 `0`，不要自行编造首测数据 |

## 三、教练端 SOP（Coach）

### 3.1 登录本人码库

1. 打开 `/coach/codes`。
2. 输入已登记为教练的本人邮箱，获取并填写验证码。
3. 登录后先核对教练身份，确认当前码库属于本人。
4. 邮箱收不到验证码时，先检查邮箱地址和垃圾邮件；仍无法登录时联系管理员核查教练身份，不要借用他人账号。

### 3.2 查看库存与复制产品码

1. 查看本人未激活产品码和可用数量。
2. 需要发给用户时，使用页面提供的复制能力复制码面，避免手工抄写错误。
3. 每个产品码只发放给一位目标用户，发放前核对接收人，不在群聊或公开渠道发布可激活码面。
4. 提醒用户在 `/check-in` 提交人工审核，并等待审核通过后开始打卡。
5. 页面出现补货提示或可用数量不足时，暂停超量承诺，联系管理员划拨。

### 3.3 发放与跟进记录

教练在线下客情流程中至少核对：

- 产品码对应的目标用户和盒规格。
- 发货或交付情况，以及管理员审核所需的凭证信息。
- 用户是否已提交申请、是否仍在审核中、是否已完成绑定。
- 用户是否理解每日打卡和邮箱备份方式。

教练端当前入口以码库查看和复制为主。规划中的 `/coach` 独立路由、左右双栏雷达与云仓看板，不作为当前已上线功能使用。

### 3.4 教练操作红线

1. 不得代用户激活、代用户打卡或批量尝试产品码。
2. 不得索要或传播用户原始身高、体重、三餐等敏感记录。
3. 不得将管理端账号、管理员邮箱或验证码转交给无权限人员。
4. 不得把页面显示的剩余数量当作财务结算凭证；实际划拨和流水以管理员核查结果为准。

## 四、管理端 SOP（Admin）

### 4.1 登录与班前检查

1. 打开 `/admin/check-in`，使用管理员邮箱验证码登录。
2. 核对当前环境和管理员身份，避免在测试环境与生产环境之间误操作。
3. 检查页面是否可正常加载，关注统计、码池、审核和雷达区域是否存在异常。
4. 开始生成、划拨或审核前，确认当次操作对象、数量和凭证均已齐备。

### 4.2 平台码池：生成产品码

1. 在平台码池区域填写本次生成数量。
2. 选择或填写盒规格，核对规格与本次生产计划一致。
3. 填写线下打款凭证号，确保凭证可与本次生成记录对应。
4. 提交前再次核对数量、盒规格和凭证号，确认后生成。
5. 生成后检查码池结果和可用数量，发现数量或规格不符时停止后续划拨，不要通过重复生成来掩盖差异。

### 4.3 平台码池：划拨给教练

1. 获取并核对目标教练的用户 ID。
2. 填写划拨数量，确认不超过当前可划拨库存。
3. 提交前核对教练用户 ID 和数量；当前流程需要准确填写教练用户 ID，不把规划中的模糊搜索下拉当作现有能力。
4. 划拨后请教练在 `/coach/codes` 核对本人可用数量和补货提示。
5. 若划错对象或数量，保留当次操作信息并走项目规定的纠正流程，不得擅自修改数据库。

### 4.4 激活人工审核

1. 打开激活人工审核列表，按申请逐项处理。
2. 核对产品码、申请用户、目标教练和发货凭证。
3. 充值码还必须核对收款凭证；凭证不全或信息不一致时不要通过。
4. 信息一致且满足业务要求时，执行通过激活；不满足要求时，执行拒绝退回并保留明确原因。
5. 审核后复核状态，确认没有重复处理同一申请。
6. 用户审核通过后应显示绑定教练和打卡额度；教练可按既有流程核对后续状态。

当前审核流程按既有归属关系处理。规划中的“人工审核支持指定归属员工”尚未实现，不得在审核备注或对外说明中宣称已经支持。

### 4.5 休眠教练人工确认托管

1. 仅在确认教练休眠且符合托管条件时进入托管处理。
2. 核对休眠教练身份、待托管对象和业务确认信息。
3. 执行人工确认前，确认平台官方账号等系统配置已经由授权人员准备完毕。
4. 托管完成后复核页面状态；失败时保留错误信息并停止重复操作，交由技术与业务负责人核查。
5. 托管属于高权限操作，不得为了清理列表或绕过激活审核而使用。

### 4.6 脱敏教练雷达

1. 在雷达区域查看服务端返回的营员代码、体重变化、腰围变化、BMI 和红黄绿灯号。
2. 指标为空时统一按 `--` 或待首测理解，不将空值解释为 `0`。
3. 灯号用于跟进优先级，不代替医学诊断，也不作为公开展示或惩罚依据。
4. 雷达只展示脱敏结果，不应出现原始 `height`、`weight` 或 `records`。
5. 若抓包或页面发现原始敏感字段，立即停止传播相关数据并上报，不通过前端隐藏来冒充脱敏修复。

### 4.7 统计与脱敏导出

1. 查看 KPI、已备份体验官表格和 D1–D21 趋势，先确认统计范围和数据日期。
2. 导出时使用系统提供的脱敏 CSV，不另行拼接敏感信息。
3. 导出文件仅用于授权业务场景，按项目数据安全要求保存和传输。
4. 统计异常时先核对数据来源和筛选范围，不通过手工改数制造一致结果。

## 五、三端协同标准流程

### 5.1 新用户发码与激活

1. 管理员生成产品码并划拨到目标教练。
2. 教练登录 `/coach/codes`，核对库存后复制并定向发给用户。
3. 教练收集并提供审核所需的发货信息；涉及充值码时，管理员同时核查收款凭证。
4. 用户在 `/check-in` 提交产品码，等待人工审核。
5. 管理员在 `/admin/check-in` 完成审核，通过或拒绝退回。
6. 审核通过后，用户确认教练绑定和打卡额度，再开始每日打卡。
7. 用户绑定本人邮箱并完成云端备份，教练继续按授权范围跟进。

### 5.2 补货流程

1. 教练发现可用数量不足或页面出现补货提示。
2. 教练向管理员提供本人身份和所需数量，不公开已有码面。
3. 管理员核对库存、教练用户 ID 和业务凭证后划拨。
4. 教练重新进入码库核对到账数量，再继续发放。

### 5.3 异常升级

出现以下任一情况时，停止重复操作并升级给管理员或技术负责人：

- 同一产品码出现重复激活、异常占用或归属争议。
- 用户更换设备后无法恢复原账号数据。
- 审核状态、打卡额度或教练绑定状态明显不一致。
- 雷达或导出内容疑似包含原始敏感数据。
- 托管操作失败，或系统配置缺失导致业务流程无法完成。

升级时记录发生时间、使用入口、账号角色、页面提示和复现步骤；不要在公开聊天中粘贴完整产品码、验证码或敏感健康数据。

## 六、数据安全与上线注意事项

1. 激活、划拨、审核、托管均以真实页面结果为准，不用口头承诺代替状态核验。
2. 本机自动保存不等于云端备份；上线培训必须明确邮箱绑定和恢复路径。
3. 雷达、统计和导出坚持最小必要原则，原始健康数据不进入教练脱敏视图。
4. 管理员不得直接在浏览器、文档或聊天工具中保存数据库高权限密钥。
5. 数据库迁移、系统配置播种、发布和回滚不属于本手册的普通业务操作，必须另行经过授权与验证。
6. 冻结 Backlog 中的功能在正式合并、验收和发布前，不得写入培训话术或作为上线承诺。
