# 官网内容信任体系与用户中心两阶段改造设计

日期：2026-10-31  
状态：已确认按两阶段执行  
适用分支：独立功能分支；不与上一轮登录转化改动混合提交

## 1. 目标

面向 30–60 岁职场人群，将品牌表达从抽象成分宣传调整为：

1. 可感知的职场饮食与体重管理场景。
2. 可核验、不过度拔高的研究与机构证据。
3. 易理解、常显可见的专业名词解释。
4. 集中管理个人打卡、趋势、海报和账号的用户中心。

## 2. 非目标与约束

- 不修改 `storage-v3` 字段、迁移规则、CSV 列定义或代表体重算法。
- 不修改 Supabase 表结构、RLS、云端 `upsert` 或管理员统计。
- 不引入全局状态库、新后端或大型 UI 库。
- 不承诺固定减重结果，不把成分研究写成产品功效，不把科学性审查批件称为临床研究报告。
- 不发布网站；每阶段仅本地验证并独立提交，等待审查。

## 3. 阶段一：官网文案、解释与信任展示

### 3.1 职场痛点与饮食场景

涉及组件：`MetabolismSignals`、`BrandPerspective`、`PlateGuide`。

- 痛点标题采用“为什么吃得少，体重还是难降？吃得不均衡，长期坚持也会更难。”
- 正文覆盖外卖、应酬饮酒、久坐和 30 岁后的体重管理压力，以理解代替自律指责。
- 删除“营养不足必然拼命囤积脂肪”的绝对因果。
- 打消顾虑采用“不靠极端节食、不追求脱水式减重”，不承诺“不拉肚子”或必然平稳减重。
- 211 保留完整结构：2 拳蔬菜、1 拳优质蛋白、1 拳主食；补充饭店应酬场景，不引导省略主食。

### 3.2 专业名词的人话解释

涉及组件：`NutritionStory`、`CategoryDifference`、`MetabolismMechanism`，必要时复用一个轻量说明组件。

- 宏量营养：基础供能营养素，包括碳水化合物、蛋白质和脂肪。
- 小分子菌糖肽：经定向酶解处理的菌物营养成分，关注营养释放与消化吸收过程。
- 麦角硫因：菌菇来源的特色营养成分，常见于抗氧化营养研究；不替代充足睡眠和均衡饮食。
- 解释采用专业名旁的常显小字，Tooltip 仅作为桌面端增强，不作为移动端唯一信息入口。
- 不把小分子菌糖肽直接等同于益生元，不承诺抗疲劳、抗衰老或肠胃治疗效果。

### 3.3 循证依据与免责声明

涉及组件：`Research`、`FormulaStrength`、页脚及局部说明样式。

- 保留研发机构公开信息链接和国医大师／院士组方背景。
- 在临床研究卡片增加醒目的“查看循证依据”按钮。
- 按钮旁明确标注“四川大学华西第四医院｜科学性审查批件 Hsy-2025043”。
- 按钮打开现有 `/images/clinical/ethics-approval.png`，不新建或伪造研究报告。
- 保留“临床研究进行中”和“研究情况与结论以正式报告为准”。
- 211 指导和打卡科普附近的免责声明使用 12–13 px、可读对比度和舒适行高；不依赖页脚极小文字承担全部合规提示。

### 3.4 打卡页情绪安抚

涉及组件：`WaterFluctuation`。

采用“早晚相差约 2 kg 的情况可能出现，不必因单次读数焦虑。重点看 21 天总体趋势”的表达，保留个体差异和持续异常需咨询专业人员的说明。

### 3.5 阶段一验收

- 新文案和链接具有组件测试。
- 211 三部分完整，无结果保证或绝对安全承诺。
- “查看循证依据”链接到真实批件，不出现“临床报告已证实”。
- 移动端无需悬浮即可阅读全部专业解释。
- 全量测试、lint、build 通过。

## 4. 阶段二：用户中心与个人数字资产

### 4.1 页面结构

涉及页面与组件：`UserCenter`、`RecordTrends`、`SevenDayCheckIn`、`SyncPanel`、`SyncModal`。

用户中心统一使用打卡页暗黑森林色与荧光绿强调色，依次展示：

1. 我的健康档案：昵称、营员代码、绑定邮箱或本机未绑定状态。
2. 数据卡片：本期累计打卡天数、本期体重变化。
3. 数字资产：历史趋势、生成海报、下载 PNG、导出 CSV。
4. 账号与同步：修改绑定邮箱、退出登录、备份与恢复入口。
5. 继续打卡入口。

### 4.2 数据来源与指标口径

- 页面挂载时通过 `loadState()` 读取现有 v3 快照；昵称读取现有名称键，不复制记录、不建立第二份状态。
- 累计打卡使用 `getCampStats(state).recordedDays`，文案明确为“本期”。
- 趋势和海报继续使用 `buildWindowRecords(state)`。
- 体重变化复用 `getRepresentativeWeight(day)`，选取本期首个与最近一个有效体重。
- 指标为“最近有效体重 − 首个有效体重”，保留正负号和 1 位小数；负值表示下降。
- 少于两条有效体重记录时显示“—”及“再记录一次即可查看变化”，不计算伪精确结果。
- 不使用“累计净减重”作为指标名，不评价变化好坏。

### 4.3 资产迁移与登录拦截

- 将趋势图、海报生成与 CSV 导出入口从打卡主流程迁移到用户中心；打卡页只保留前往用户中心的入口。
- 继续复用 `RecordTrends` 和 `createRecordPoster`，不重写图表或海报绘制。
- D3 软提醒仍留在打卡流程。
- D7 硬拦截随趋势和海报迁至用户中心，触发规则不变：匿名、已配置 Supabase、开营自然日达到 D7。
- D3“暂不”不豁免 D7；已绑定用户不拦截。
- 绑定成功后继续原先请求的趋势或海报操作。
- 用户中心挂载现有 `SyncPanel` 作为同步状态和统一弹窗宿主，避免复制 OTP 与弹窗状态机。

### 4.4 修改绑定邮箱

- 仅已绑定用户显示修改入口。
- 复用 Supabase `updateUser({ email })` 与 `verifyOtp({ type: "email_change" })`。
- 新邮箱验证成功前保留原邮箱状态；失败时显示可读错误，不影响本机或云端记录。
- 成功后保持原 `auth.uid`、营员代码和云端记录不变，并广播统一同步状态更新。

### 4.5 退出登录

- 调用 Supabase `signOut()`，随后广播邮箱为空，刷新 Header 和用户中心状态。
- 默认保留本机打卡记录，不删除云端数据，不重置营员代码。
- 提示“退出不会删除本机或云端数据；再次登录可恢复云端记录”。
- 退出失败时保持当前页面数据并显示错误，不做伪成功跳转。

### 4.6 空态与异常

- 无记录：统计卡片显示 0 或“—”，趋势显示记录引导，海报按钮仍按现有空记录规则处理。
- 匿名：允许查看本机档案；账号安全区展示绑定引导，D7 资产继续硬拦截。
- 未配置 Supabase：本机统计与资产可用，隐藏修改邮箱、退出和云同步入口。
- localStorage 不可用：沿用现有降级行为，不造成页面崩溃。
- Canvas 不可用：保留现有海报错误提示，不影响趋势和 CSV。

- 循证按钮目标与证据等级表述。

### 阶段二测试

- 趋势和海报只在用户中心渲染，打卡页入口可到达。
- D3／D7、取消后保存、绑定后继续操作、已绑定不拦截。
- 修改邮箱成功与失败、退出后本机数据保留、未配置 Supabase 降级。

## 6. 提交顺序

1. 阶段一：官网内容与信任展示，独立提交。
2. 阶段二：用户中心只读档案与统计。
3. 阶段二：趋势、海报、CSV 迁移及 D7 回归。
4. 阶段二：修改邮箱与退出登录，独立提交。
5. 全部审查通过后，才另行讨论合并、推送和发布。
