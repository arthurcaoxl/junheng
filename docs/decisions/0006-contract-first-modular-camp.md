# ADR 0006：训练营采用契约优先的模块化单体

- 状态：已接受（架构预留，未实现）
- 日期：2026-10-29

## 背景

未来需要招募、报名、审核、支付和营员身份能力，同时要求现有 v1.7.0 完全不变，并能随需求增减模块。当前静态网站没有服务端业务，过早确定数据库或支付渠道会锁定实现细节。

## 决策

采用“模块化单体＋稳定契约＋可替换适配器”。先定义模块数据所有权、命令、事件、状态机、异常规则和 JSON Schema，再分别规划实现。

`camp-flow` 只拥有流程实例与编排日志，不拥有业务状态。跨模块状态变化只能由所属模块命令完成；payment 不得直接修改 enrollment。流程策略决定是否需要审核和支付。

本机 storage-v3 与未来 identity 隔离，匿名 `userCode` 不作为登录账号。支付渠道和 Supabase 仅通过适配器接入。

## 非目标与零影响边界

- 不写业务页面、API、SQL 迁移或真实支付实现。
- 不连接 Supabase，不处理真实个人数据，不发布网站。
- `apps/web` 保持基线树 `6e193dfd7ff220d67038987773d8743e44051cf3`，不 bump 版本。
- 契约校验脚本独立于现有 45 项 Vitest；docs 与 scripts 不进入 dist。

## 影响

未来可按模块实现并替换渠道，免费营或取消审核只调整流程策略。实现前仍需分别完成数据隐私、RLS、支付安全、部署和对账设计；本 ADR 不授权处理真实数据或资金。
