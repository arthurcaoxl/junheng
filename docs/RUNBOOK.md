## 第一部分：五角架构核心铁律

1. **只认物理**：只认 Git 物理输出（hash、log、status）、测试退出码与代码行号，绝不信任何口头汇报或"大概"。
2. **契约即代码，配置即外置**：所有业务规则必须在契约中有物理映射；严禁在 SQL/前端中硬编码密钥、UUID、策略。
3. **防呆与脱敏**：物理脱敏必须在 SQL/RPC 层完成（如 Vault），严禁依赖前端遮罩；断网即停机，沙盒必 commit。
4. **最小权限**：新建 RPC 必须包含 `auth.uid()` 角色校验。严禁使用 `git add .`。
5. **密钥入 Vault（P0 拆弹教训）**：严禁在托管型数据库（如 Supabase）使用 GUC 参数（如 `ALTER DATABASE ... SET app.xxx_pepper`）硬编码密钥——该操作会被平台权限直接拒绝。所有高敏配置必须推入平台原生保险库（如 Supabase Vault），RPC 层通过 `vault.decrypted_secrets` 动态读取。
6. **终态必净**：任何"已合并/已修复/已推送"的结论，必须附带 `git status -sb` 输出作为终态证据。工作区存在任何未提交文件（`M` / `??`），结论一律作废。
7. **合并黑洞防御（V2.1 新增）**：遇到多父节点 Merge Commit，**严禁 `cherry-pick --skip`**。`--skip` 会把整个 commit 的改动物理吞掉（2146 行代码凭空消失的事故原型）。必须使用 `git cherry-pick -m 1 <hash>` 拆包，取主分支视角的净变更；若 `-m 1` 拆包结果异常，立即中断排查，严禁蒙眼推进。

## 第二部分：角色定义与启动（含交接 Prompt 模板）

### 角色定义

- **主脑（DeepSeek — 架构审查者）**：全局统筹、发布标准 Prompt、审查副脑降噪包、进行最终裁决。**绝不直接阅读大文件、完整测试日志或 `git show` 长篇输出。**
- **裁判（人类 — 执行监督者）**：原样传达主脑 Prompt、操作主工作区（建沙盒、多模块合并）、收集物理证据、调度副脑降噪。**拥有物理覆盖（cp）与合并冲突的最终处置权。**
- **主任务 1104（项目经理 / Orchestrator）**：**绝对禁止亲自下场编写业务代码或 SQL**。负责主仓库之外的沙盒建立（`git worktree`）、大需求拆解、向开发子任务派发模块级工单、汇总各模块 commit 与测试结果。
- **逻辑中枢（子任务 0 — Tech Lead）**：不写业务代码，只负责将长文档提炼为结构化契约（TypeScript Interface），产出《业务逻辑中枢字典》。文档没写清的业务边界直接标注 `[待确认]`，严禁脑补。
- **开发子任务（如 Kimi 等）**：开发执行者。在 1104 分配的隔离区中编写代码，按模块独立 commit，跑定向测试，严禁跨模块混提。
- **副脑（Kimi 或另一个 DeepSeek 窗口 — 降噪分析者）**：负责将冗长的测试日志、复杂的 diff 转化为高信息密度的"物理证据包"，供主脑审查。**不参与架构决策，不指挥裁判，只做"输入 → 压缩 → 输出"。**

适用场景：需要吞下长篇文档（如 V7.1 指南、商业模型），生成或更新《业务逻辑中枢字典》。

发给 Kimi 的 Prompt：

```text

你是项目的"逻辑中枢（Tech Lead）"。你不写业务代码，只负责将长文档提炼为结构化契约。
【动作】

2. 阅读 `docs/architecture/` 下的商业文档。

【纪律】
必须使用 TypeScript Interface 定义核心状态机和脱敏接口。
如果有文档没写清的业务边界，直接标注[待确认]，严禁自己脑补。
```

## 第三部分：裁判实操 SOP（全链路执行标准）

这是每次任务在物理世界的标准流转动作。

### 阶段 A：核验与派单

1. 接到主脑指令，原样复制标准 Prompt 发给 1104（PM）。
2. 收到主任务的 Hash 后，在 VS Code 终端执行：

```bash
cd <主工作区绝对路径>
git pull origin main
bash scripts/pre-flight.sh
# 切分支并强制推送到远端
git switch -c <分支名>
git push -u origin <分支名>   # ⚠️ 必须做，否则云端 AI 找不到分支，会产生平行宇宙
```

3. 严格要求 1104 基于最新 `origin/main` 使用 `git worktree` 建立隔离沙盒（见第七部分 7.1）。

### 阶段 B：并发开发与监视

1. 1104 将任务拆解为 A/B/C 模块，派发给不同开发子任务并行开工（见第七部分 7.2）。
2. **副脑降噪**：测试报错或 diff 过长时，先丢副脑降噪，再把浓缩包交主脑审查，**严禁直接把几百行日志贴给主脑**。
3. 红灯日志经副脑浓缩后贴给主脑，确认失败原因是否与业务缺失一致（防止伪实现）。裁判看代码时，使用 `git diff --cached -U0` 只取增删行，防 Token 爆炸。
4. 绿灯通过后，让子任务执行 `git add <具体文件>` 并在沙盒按模块独立 commit，汇报沙盒路径和 Commit Hash。
5. 裁判仅盯盘，不干预开发；遇到断网/幻觉导致的越权，立刻触发停机。

### 阶段 C：合并落盘（针对并发多模块提交的验收标准）

由于 PM 采用并发调度，开发子任务会产生多个 commit：

```bash
# 1. 物理摘取：裁判接收 1104 汇总的多个模块 commit hash
git fetch <沙盒路径> <分支名>

# 2. 逐个合并，防冲突
git cherry-pick <模块A_hash> <模块B_hash>

# ⚠️【合并黑洞防御】若某 hash 是多父节点 Merge Commit，Git 会拒绝普通 cherry-pick。
#    严禁使用 `git cherry-pick --skip` 跳过——这会把该 commit 的改动物理吞掉
#    （2146 行代码全丢的事故原型）。
#    必须使用 `git cherry-pick -m 1 <hash>` 拆包，取主分支视角的净变更；
#    若 -m 1 拆包结果异常（diff 为空或明显缺失），立即中断排查，
#    回到源沙盒用 `git show <hash>` 核实真实改动范围，严禁蒙眼推进。

# ⚠️ 若 cherry-pick 报 CONFLICT，严禁子任务自行解决，
#    必须由裁判在主工作区手工做文本级合并，git add 冲突文件后再继续。

# ⚠️【静默合并防御】若 cherry-pick 自动合并（无 CONFLICT），但全量测试出现大面积
#    SyntaxError 或逻辑缺失，严禁让 AI 逐行修 bug。
#    必须由裁判去原始沙盒（PM 目录）执行 `cp <原版> <目标>` 物理覆盖，
#    这是最快、最安全的止损手段。

# 3. 合并后，在主仓库跑全量构建与测试，确保 100% 全绿
bash scripts/pre-flight.sh
npm test -- --run --reporter=dot  # 静默模式防刷屏

# ⚠️【基线不缩水验证】合并后必须比对测试基线数量（合并前记录测试总数）。
#    若测试项减少（如 456 → 452），说明测试文件被 Git 静默覆盖，
#    严禁带着缩水的测试基线推流。
#    溯源命令：`git log -S '<丢失测试的关键字符串>' --oneline --all`，
#    定位吞掉测试的 commit 后强制补合，恢复至基线数量方可继续。

# ⚠️【契约冲突裁决法】若 Markdown 台账（WORKLOG.md / AGENTS.md / 中枢字典）
#    出现冲突：一律保留 HEAD 的历史痕迹，采纳 Incoming 的新版本号与新条目，
#    然后手工清理重复条目。严禁 Accept Both 直接污染台账，
#    严禁 Incoming 覆盖抹掉 HEAD 已登记的历史记录。

# 4. 【强制洁净检查】全绿后，执行最终推送前，必须死守 git status
git status -sb
# ⚠️ 输出必须仅含 `## main...origin/main`，绝对严禁带有任何 `M` 或 `??` 未提交文件。
git push origin main

# 5. 唤醒主任务更新台账
# 向 1104 发送："10.7 已合并，Hash 为 xxx。请更新 WORKLOG.md 和 AGENTS.md 台账，并 push。"
```

## 第四部分：断网/断联紧急兜底指南

当子任务 AI 提示"网络连接失败，无法推送"时，裁判必须立刻介入，严禁 AI 尝试任何越权操作（如调用 GitHub API 伪造提交）。

操作步骤：

1. 命令子任务："立刻停止操作，输出你的 git diff 或 git show。"
2. **断网即停机**：若沙盒内无法 `git fetch` 远端，绝不越权强推。
3. **离线摆渡**：启用 `git bundle create` 生成离线基线包，由裁判摆渡到主工作区后 `git bundle unbundle` 摘取。
4. **网络隔离下的依赖**：前端 `npm install` 若因断网失败，严禁瞎造依赖，必须由裁判注入现成的 `node_modules` 或等待网络恢复。
5. 裁判在 VS Code 中手动将 AI 生成的代码 Diff 应用到自己的 VS Code 工作区，自己执行 `git add` 和 `git commit`。
6. 继续执行正常的审核与合并流程。

## 第五部分：AI 幻觉与撒谎的识别与治疗

如果大模型出现以下症状，请立刻使用红线法则：

| AI 幻觉症状 | 治疗方法（裁判执行） |
|------|------|
| 虚报合并/推送："我已经合并到 main 了。" | 裁判直接敲击 `git log --oneline -1 origin/main`。如果是旧的，立刻打回："远端没有你的提交，立刻重推或报告网络错误。" |
| 伪实现："我已删除了敏感字段。" | 要求 AI 贴出 TypeScript 的 Interface 定义和 SQL 的 SELECT 语句。如果它是用前端 `.filter()` 过滤的，直接判定不合格，打回重写。 |
| 假装测试通过："红灯测试通过了。" | 不认截图，只认终端输出的退出码（Exit code 0）、测试用例数（Test Files X passed / Tests Y passed）。若报"TDD 红灯转绿"，必须提供红灯时的报错记录。 |
| 暗箱重构：说删了 RPC，实际只删了一行。 | 审查 `git diff --stat` 中的 `-`（删除行数）。必须确认旧函数被 DROP，而不是新增了重载。 |
| 无行号结论："已修复。" | 必须让它出示 `git diff` 和对应代码的绝对行号。**没有行号的结论作废。** |
| 只交全绿结果："Bug 已修复，测试全绿。" | **代码级红灯证明**：必须附上修改前后的测试对比（修改前的报错截图/终端失败日志，修改后的 Exit code 0）。严禁直接交出全绿的测试结果。 |
| 终态残留："已全部提交/推送。" | 必须出示 `git status -sb`，输出仅允许 `## main...origin/main`。出现任何 `M` 或 `??` 即打回："有 N 个未提交文件，先 commit 或物理删除后再报。" |
| 吞并式合并："该 commit 已跳过/已包含。"（V2.1 新增） | 必须出示该 hash 的 `git show --stat <hash>`。若改动行数与摘要不符，判定为 `--skip` 吞包事故，立即用 `-m 1` 拆包重摘，严禁再次跳过。 |

## 第六部分：核心工程铁律与避坑指南（血泪教训库）

1. **物理隔离**：绝对锁定绝对路径（/Users/mac/Documents/kimi/tasks/...），开工前必跑 `bash scripts/pre-flight.sh`。严禁跨目录操作。
2. **文件级暂存**：严禁 `git add .`，只能显式 `git add <file>`。绝对禁止夹带 `tools/sandbox/sandbox.html`。
3. **物理脱敏**：前端隐藏不算脱敏，必须在 SQL/RPC 层剥离敏感字段。
4. **配置与逻辑分离**：任何业务参数（限额、次数、有效期）必须从 SystemConfig 读取，缺失即 fail-closed，严禁在代码中硬编码。
5. **禁止"伪测试"**：红灯测试必须针对真实行为（运行时计数、并发），严禁仅用正则匹配 SQL 文本冒充行为测试。
6. **密钥入 Vault**：严禁在托管型数据库（如 Supabase）使用 GUC 参数硬编码密钥。所有高敏配置必须推入平台原生保险库（如 Supabase Vault），RPC 层通过 `vault.decrypted_secrets` 动态读取。
7. **SSOT 单一事实来源（P0-2 教训）**：同一业务实体（如教练、用户），全库必须有且只有一条物理事实判定来源。新建 RPC 时，严禁凭感觉写 EXISTS 判定，必须遵守《业务逻辑中枢字典》定义的统一关联表。
8. **静默合并止损**：Git 自动合并无冲突 ≠ 语义正确。一旦合并后测试大面积崩溃、权限丢失，**严禁 AI 逐行修 bug**；最高效、最安全的手段是裁判去源沙盒 `cp <原版> <目标>` 物理覆盖。
9. **终态洁净**：push 之前必须执行 `git status -sb` 终态检查，绝不让任何未提交文件（`M` / `??`）活过合并时刻。远端构建报错而本地全绿时，第一反应是检查是否有补丁文件停留在工作区。
10. **合并黑洞防御（V2.1 新增）**：遇到多父节点 Merge Commit，`git cherry-pick --skip` 是物理级自杀操作——整个 commit 的改动会被静默吞掉。唯一正确姿势：`git cherry-pick -m 1 <hash>` 拆包；拆包异常立即中断排查。
11. **测试基线守恒（V2.1 新增）**：合并前后测试总数必须守恒。测试项减少 = 有测试文件被静默覆盖 = 合并不合格。用 `git log -S` 溯源，强制补合至基线数量后才允许推流。

| 事故现象 | 根因 | 裁判防御手段 |
|------|------|------|
| 平行宇宙：AI 在旧目录干活，主目录没变 | 绝对路径错乱 | 指令必带 `cd <绝对路径>`；子任务必须 commit，裁判用 cherry-pick 物理打通。 |
| 脏工作区合并：带入未跟踪的沙盘文件 | 惯性使用 `git add .` | 合并前后必跑 `git status --short`，校验文件变更列表。 |
| 台账恶性冲突：合并时 WORKLOG 满是冲突标记 | 多人并行改同一文档 | 绝不 Accept Both 污染 YAML。裁判手工解，保留双方记录。 |
| 基线漂移：以"旧副本"或"不知名路径"为基准 | HEAD 不干净，未对齐 `origin/main` | 开工前强制对齐 `origin/main`，pre-flight 必过。 |
| 越权修改：PM 写代码、子任务跨界 | 任务边界不清 | 明确边界：PM 绝不改代码，子任务绝不跨界。 |
| 并发合并冲突：多模块修改同一文件（如 `App.tsx`、`WORKLOG.md`） | 并发开发的固有代价 | cherry-pick 报 CONFLICT 时严禁子任务自行解决，裁判在主工作区手工文本级合并后再继续。 |
| 硬编码灾难：密钥（如 Vault pepper）或真实业务参数写死进代码 | 图省事、绕过 SystemConfig | 直接打回重做。 |
| GUC 密钥被拒：`ALTER DATABASE ... SET app.box_code_pepper` 被 Supabase 权限拒绝 | 误用托管库 GUC 参数承载密钥 | 高敏配置一律推入 Supabase Vault，RPC 层 `vault.decrypted_secrets` 动态读取。 |
| 双口径事故（P0-2）：`camp_admins` 与 `user_coach_relation` 两套教练身份口径并存 | 同一实体存在多个物理判定来源 | 全库只保留一条事实判定来源；新建 RPC 严禁凭感觉写 EXISTS，必须遵守中枢字典的统一关联表。 |
| 静默自动合并：终端未报 CONFLICT，但测试大面积崩溃、权限丢失 | Git 自动合并覆盖了相邻的非冲突代码（如 mock 代码、Service 逻辑） | 放弃手写修复，直接去源沙盒 `cp` 覆盖测试文件和 Service 层源文件。 |
| 终态漏推：已 push，但远端构建依然报错 | 关键补丁文件停留在工作区（`M` 状态），未执行 commit | push 前死守 `git status`，绝不让任何未提交文件留到合并之后。 |
| 合并黑洞（V2.1 新增）：多提交合并后，核心文件莫名消失（如 2146 行代码全丢） | 遇到 merge 节点，裁判使用 `cherry-pick --skip` 跳过，整个 commit 改动被物理吞掉 | 使用 `git cherry-pick -m 1 <hash>` 拆包取主分支净变更；若拆包异常，强制中断排查，严禁再次 `--skip`。 |
| 测试基线缩水（V2.1 新增）：合并后测试从 456 掉到 452 | 测试文件作为非冲突代码被 Git 静默覆盖 | 强制比对合并前后的测试数量；用 `git log -S` 溯源丢失的测试并强制补合，恢复基线后才允许推流。 |

> **V2.0 金句**："Git 的静默合并是并发开发的隐形杀手，裁判的 cp 物理覆盖是最高效的特效药。"
>
> **V2.1 金句**："`--skip` 不是跳过麻烦，是把整段代码推进黑洞。merge 节点面前，只有 `-m 1` 拆包这一条活路。"

## 第七部分：PM 并发调度协议（Agent Orchestration）

为了极致压缩交付周期，PM（1104）必须采用多智能体并发机制：

- **7.1 物理隔离**：PM 派发并发任务前，必须用 `git worktree add ../_task-xxx -b feat/xxx` 建立专属物理目录。绝不允许多个子任务在同一个文件树中写代码。
- **7.2 模块拆解**：大需求必须被切分为无交集或弱交集的模块（如：前端 UI 组件、后端 RPC 与迁移、单元测试等）。
- **7.3 原子提交**：每个子任务完成任务后，必须按照模块边界独立 commit（如 `feat(admin): ...`、`fix(rpc): ...`），严禁将多个模块揉进一个 commit。
- **7.4 聚合验收**：所有并发子任务结束后，PM 汇总所有的 commit hash、`git diff --stat` 和各自模块的测试结果，统一向裁判交卷。
- **7.5 禁止 merge 式提交（V2.1 新增）**：子任务提交必须保持线性历史（rebase 后提交），严禁向交卷分支引入 merge commit。merge 节点会让裁判的 cherry-pick 进入黑洞风险区，违背铁律 7。

## 第八部分：上下文减负与主脑无损切换 (Offline Failover)

大模型主脑在上下文严重超载时，接力信息不得依赖濒死的主脑自行总结，生成权由外部常驻角色接管。

- **8.1 主脑接力上下文资产化**
  - **物理侧（1104维护）**：在 `docs/WORKLOG.md` 顶部维护 `handoff_snapshot`（当前版本、活动任务、最后 Hash、测试基线、交接嘱托）。
  - **语义侧（中枢0维护）**：在 `docs/architecture/brain-handoff-context.md` 中维护当前防线索引。
- **8.2 主脑无损切换 SOP**
  1. **冻结旧对话**：裁判停止向过载的主脑发送新任务。
  2. **提取物理快照**：向 1104 发送指令："输出最新接力快照"。
  3. **提取架构防线**：向中枢 0 发送指令："输出最新防线提醒"。
  4. **唤醒新主脑**：新开 DeepSeek 对话，发送【主脑恢复与接力】模板，5 秒满血复活。
