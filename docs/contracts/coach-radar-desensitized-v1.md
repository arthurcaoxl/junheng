# 教练雷达脱敏契约 v1

- 状态：裁判终裁已落实，未实现
- 所属体系：10.1 打卡 App 业务重构契约
- 交付边界：仅逻辑契约；不包含 SQL、迁移、RPC 或前端实现

> 依据裁判终裁与 V7.1 运营指南，重点落实 8.1 雷达定位、8.2 客情节奏及 4.4 每日用户服务检查。

## 1. 目标与权限边界

`get_coach_radar_v1()` 用于教练和被授权 staff 的服务跟进，不是原始健康档案查询、财务分润查询或公共统计接口。

- coach：只能查看自己当前名下用户的雷达结果。
- staff：只能查看自己被分配教练当前名下的用户，且必须通过同一 RPC 的服务端权限过滤。
- admin：可按管理职责查看，但仍受本契约最小返回字段约束。
- 调用者身份只取服务端 `auth.uid`；不得通过传入 coachId、staffId、userCode 或邮箱切换查看范围。
- 未认证、角色无效、分配已撤销或超出分配范围时返回空结果或 `FORBIDDEN`，不得返回目标用户是否存在的额外信息。
- 用户托管至 `PLATFORM_ID` 后，原 coach 及其 staff 立即失去该用户雷达访问，旧分配不授予平台用户可见性。

角色与分配关系以 `staff-role-permissions-v1.md` 为准。

## 2. RPC 签名与执行约束

```text
get_coach_radar_v1()
```

v1 不接受客户端范围参数。服务端根据调用者角色和当前有效分配关系自动确定可见集合，避免“先传教练 ID 再补权限检查”的越权设计。

- 查询为只读、同步返回，不修改打卡、归属、库存或财务状态。
- `alert_level` 必须由 SQL 层在服务端计算；前端不得计算、推断、覆盖或根据其他字段重建灯号。
- 其他差值和 BMI 也只能由服务端或受控适配器计算，前端仅展示已批准结果。
- 任何直接表访问、后续字段扩展和导出功能都必须重新执行同等权限与脱敏评审。
- 浏览器仅使用 `anon key`；服务端必须再次鉴权，不能信任前端隐藏按钮。
- 财务分润字段、金额、教练收益和奖励负债不得进入本 RPC。

## 3. 返回字段与绝对禁止项

### 3.1 用户级返回字段

10.5 开工令将本阶段用户行收敛为以下五个字段；后续恢复 `stage` 必须重新评审：

| 字段 | 类型与单位 | 规则 |
| --- | --- | --- |
| `camper_code` | string | 受限体验官代码的雷达展示映射，不是 `auth.uid`，不得作为登录或授权依据。 |
| `weight_delta` | number \| null，kg | 当前有效代表体重减初始有效体重；原始体重不返回。 |
| `waist_delta` | number \| null，cm | 当前有效腰围减初始有效腰围；原始腰围不返回。 |
| `bmi` | number \| null | 服务端根据当前身高和当前有效代表体重计算；身高不返回。 |
| `alert_level` | string | 仅允许 `red / yellow / green`，由 SQL 层按第 4 节计算。 |

缺失身高、初始值或当前有效值时，相应指标返回 `null`，不得用 0 冒充，也不得为了计算差值返回原始值。v1 不规定前端展示小数位；服务端以完整计算值生成结果，展示舍入不得参与阶段或灯号判断，数值负零统一归一为 0。

### 3.2 已批准的教练级库存预警字段

如雷达确需展示补货提示，只允许在用户行之外返回当前可见教练的 `unused_codes_count`、`restock_point`、`restock_alert` 三个库存汇总字段。它们不得进入用户行，不得夹带产品码、订单、用户消耗明细或财务信息。

### 3.3 绝对禁止返回

以下字段不得以顶层、嵌套、数组、别名、调试字段或错误详情形式出现：

- `height`、`weight`、`height_cm`、`initial_weight_kg`
- `records` 或任何原始打卡记录集合
- 原始体重、原始腰围及可反推这些原始值的字段组合
- 饮食照片、每日行为项、联系方式、姓名、邮箱、`auth.uid`
- 完整产品码、支付信息、财务分润、原始复购记录、精确最后打卡时间
- 可还原上述信息的序列化快照、导出载荷或错误详情

## 4. `alert_level` 逻辑

灯号由 SQL 层使用服务端当前日期和已同步的有效打卡日期计算，优先级如下：

| 优先级 | `alert_level` | 条件 |
| --- | --- | --- |
| 1 | `red` | 已结营但未复购，即 `churn = true`；无论最近是否打卡都直接红。 |
| 2 | `red` | 从未产生有效打卡。 |
| 3 | `red` | 服务端当前日期距最后一次有效打卡日期大于或等于 3 个自然日。 |
| 4 | `yellow` | 不满足红灯，且距最后一次有效打卡日期恰好等于 2 个自然日。 |
| 5 | `green` | 其余正常状态，即距最后一次有效打卡日期为 0 或 1 个自然日且未结营流失。 |

统一边界：

- 日期差统一使用 `Asia/Shanghai` 自然日：`当前本地日期 - 最后有效打卡本地日期`。当天打卡为 0，前一天为 1，前两天为 2，三天及更早为大于或等于 3；不使用客户端时钟。
- 本机 `records` 只能作为受控同步和服务端判定的输入，绝不通过 RPC 返回；无法证明存在有效打卡日期时不得默认判绿，按无可信打卡证据的红灯处理并记录数据质量审计。
- 结营后不存在有效充值码激活即视为未复购；有效充值激活成立后不再满足该流失条件。充值激活被撤销后必须重新评估，不得保留虚假的正常状态。
- `alert_level` 只有 `red / yellow / green`，不增设其他值，不允许前端根据原始记录重新计算。

## 5. 指标计算口径

1. 当前体重必须沿用 `storage-v3` 的 `getRepresentativeWeight` 语义，由服务端或受控适配器计算，不在雷达另写一套早／中／晚权重。
2. 衣物扣减只读取每日快照，不得用当前全局默认值重算历史，更不得通过雷达修改任何每日记录。
3. 初始体重遵循用户显式初始值优先、缺失时按既有契约推导的规则；原始初始体重仍不得返回。
4. 当前值取当前有效激活及 `stage` 对应业务窗口内日期最晚的有效值；跨阶段历史不得混入当前差值。
5. BMI 使用未做展示舍入的值参与后续分类，展示精度与分类阈值分离；本 RPC 不返回身高。
6. 数据不足时相关派生指标为 `null`，其他已批准字段仍可返回；不得为补齐指标回传 `records`。

## 6. 补货预警纯函数契约

函数签名为 `checkRestockAlert(unusedCodesCount, restockPoint = 12): boolean`，逻辑恒等于 `unusedCodesCount < restockPoint`。

- 默认 `restockPoint = 12`，因此 11 个触发，12 个不触发。
- `unusedCodesCount` 只统计 `unused` 产品码，不包含 `pending_review / active / revoked`；审核拒绝后的 `revoked` 码不得回补。
- 两个参数都必须是非负安全整数；非法值应抛出参数错误或由调用方在边界拒绝，不得静默截断、取绝对值或四舍五入。
- 函数保持同步、确定、无副作用；不读取数据库、DOM、网络、当前时间或沙盘引擎。
- 该函数只判断库存预警，不决定教练是否具备拿货资格，也不直接创建补货订单。

## 7. 雷达 SOP 与工单衔接

| 灯号 | 业务动作 | 完成记录 |
| --- | --- | --- |
| `green` | 及时肯定、鼓励保持，不夸大结果，不创建高优先级催办。 | 表扬触达与后续安排。 |
| `yellow` | 询问记录减少、阶段波动或执行困难的原因，给出一个可执行支持动作，必要时复查。 | 问题原因与解决方案。 |
| `red` | 优先召回长期未记录、流失风险、结营未复购或服务争议用户；无法解决时升级员工或平台客服。 | 召回结果与升级记录。 |

- 每日按红、黄、绿顺序处理，工单状态采用 `已触达 / 待回复 / 已解决 / 需升级`；异常未解决不得静默关闭。
- v1 依指南执行每日检查、每周复盘和必要的平台升级，不另设数字化处理时限或提醒次数。
- 工单只保存不透明用户引用、`alert_level`、原因码、责任人和状态，不把原始健康记录复制到工单。
- 归属休眠转平台后，新工单责任人为平台；历史工单保留原处理链，未结工单在复核后转平台责任队列，原 coach 及其 staff 不得继续处理。
- 用户拒绝联系、号码无效、已复购等关闭原因使用规范原因码，不记录不必要的自由文本敏感信息。

## 8. 审计、速率与数据保护

- 记录调用者、角色、结果数量、查询时间、关联 ID 和授权结果，不记录返回的原始敏感载荷。
- 对异常高频查询、连续角色切换和分配撤销后的访问进行安全审计。v1 不新增固定频率业务阈值，限流配置属于安全实现，不得替代权限检查。
- 雷达页面不得提供“导出原始记录”或经浏览器隐藏字段绕过脱敏的能力。
- 缓存键必须包含调用者与授权版本；角色、归属或分配变化后立即使旧缓存失效。
- 公共事件不得携带雷达用户行；CEO 沙盘如需使用，只能接收另行批准的最小聚合快照，不能复用本 RPC 的个人级结果。
