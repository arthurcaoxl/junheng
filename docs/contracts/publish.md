# 发布契约

## 固定目标

- 当前版本：`v1.8.0`
- 发布方式：在获所有者明确授权的 Kimi 会话中使用 `kimix website publish`
- 网站 ID：`1a170fd8-b362-873e-8000-0000c5bec604`
- 线上地址：`https://rtrzqrxly4mlo.ok.kimi.link`
- CI、本地构建和预览均不具有发布权限。

## 静态托管特性（v1.7.2 验证）

托管平台为**精确文件路径**静态服务：无 SPA fallback、无目录索引（`/h5/` 与 `/h5` 均 404，仅 `/h5/index.html` 200）。因此：

- 站点 `base` 必须为绝对路径 `/`（`vite.config.ts`），相对路径在子目录入口会断；
- 每个客户端路由需在构建产物中有对应静态入口：`postbuild` 会将 `index.html` 复制为 `dist/check-in/index.html`；
- 打卡页公开深链形式为 `https://rtrzqrxly4mlo.ok.kimi.link/check-in/index.html`，站内链接仍用客户端路由 `/check-in`；
- 未来新增顶层路由时，必须同步 `postbuild` 复制规则并在发布后验证深链。

## 版本号

采用语义化版本 `MAJOR.MINOR.PATCH`，Git 标记使用 `vX.Y.Z`。

- PATCH：文案、样式、缺陷修复，无数据结构或公开行为破坏。
- MINOR：向后兼容的新功能、新契约能力。
- MAJOR：不兼容的数据结构、迁移或公开行为变更。

发布前同步 `apps/web/package.json` 与锁文件中的版本；数据兼容性变更必须先更新存储契约和 ADR。

## 发布 checklist

- [ ] 变更已在独立分支审查，所有者明确批准本次发布。
- [ ] 目标网站 ID 和线上地址与本文一致，未切换目标。
- [ ] `npm ci`、`npm run lint`、`npm test` 全过；当前基线为 61 项测试。
- [ ] `npm run build` 成功，重建产物与已验证基线完成文件级比对。
- [ ] 存储迁移、CSV、分享页和关键交互已按变更范围验证。
- [ ] 无 `.env`、凭据、验证截图或原始大素材进入发布产物。
- [ ] 版本号、变更说明、回滚版本和 `ops/logs/` 文本记录已准备。
- [ ] 仅由获授权的 Kimi 会话执行 `kimix website publish`。
- [ ] 发布后检查首页、`/h5/index.html`、分享图与关键打卡流程，并记录结果。

## 回滚规则

1. 发现阻断性问题时停止后续发布，保留错误与验证日志。
2. 选择最近一个已验证的 Git 提交和对应版本，不以未验证的最新构建回滚。
3. 从该提交干净执行 `npm ci`、测试和构建，确认回滚产物。
4. 经所有者明确授权后，由同一受控 Kimi 会话向同一网站 ID 重新发布该已验证版本。
5. 回滚后复查线上关键路径并记录原因、源版本、目标版本、提交和结果。

回滚是“重新发布最近已验证的静态产物”，不假定托管平台提供一键历史恢复；涉及未来数据库时，必须另写数据迁移回滚契约。
